# tube-leak

Кросс-платформенное десктопное приложение для скачивания видео с YouTube.

**Статус: greenfield.** Кода пока нет — файл описывает целевую архитектуру и соглашения. По мере появления кода уточняй разделы «Структура» и «Команды» фактическим состоянием репозитория, а не планами.

**Windows-установщик собирается с macOS** (TL-126, 2026-09-18, проверено: `tube-leak_0.1.0_x64-setup.exe`, 77 МиБ). Путь официальный, но помечен в документации Tauri как «последнее средство»; MSI так не собрать — WiX только под Windows. Последовательность:

```bash
brew install nsis llvm
export PATH="$HOME/.cargo/bin:/opt/homebrew/opt/llvm/bin:/opt/homebrew/opt/rustup/bin:$PATH"
export XWIN_CACHE_DIR=$HOME/.cache/cargo-xwin      # 1,1 ГиБ, вне репозитория
rustup target add x86_64-pc-windows-msvc
cargo install --locked cargo-xwin
node scripts/fetch-binaries/index.mjs --target x86_64-pc-windows-msvc
npm run tauri build -- --runner cargo-xwin --target x86_64-pc-windows-msvc --bundles nsis
```

Два шага, которых нет в рецепте документации Tauri, и без них всё встаёт: `$HOME/.cargo/bin` в `PATH` (Tauri ищет раннер **отдельным бинарником**, хотя `cargo xwin` при этом работает) и доставка sidecar под целевую тройку до сборки (иначе `tauri_build` падает на `externalBin`). Отдельная формула `lld` не нужна: линкует `rust-lld` из rustup. Наши `#[cfg(windows)]`-ветки скомпилировались без единой правки, `libsqlite3-sys` с `bundled` под clang-cl 23 собрался. **Это артефакт, а не проверка:** установка, WebView2, распаковка `resources/yt-dlp.zip`, запуск sidecar, `taskkill /T`, «показать в папке» и SmartScreen требуют настоящей Windows (#70).

**TS-типы границы генерируются, а не пишутся руками (TL-51).** Источник —
`src-tauri/src/types.rs`, генератор — `ts-rs` (dev-зависимость, derive под
`#[cfg_attr(test, ...)]`, в релизном графе ноль новых крейтов). Результат
лежит в репозитории: `src/types/generated/{sidecar,ytdlp,probe,download}.ts`.

Сторож — сам `cargo test`: он строит эталон во временный каталог и
сравнивает с закоммиченным, ничего не переписывая. Перегенерация — только
по явному требованию:

```bash
cd src-tauri && TUBE_LEAK_UPDATE_TS_BINDINGS=1 cargo test --locked types::bindings
```

Правка сгенерированного файла руками роняет тесты; менять контракт нужно
в Rust. Новые типы границы объявляются в `types.rs` **выше** маркера
`mod bindings;` — всё, что ниже, сторожа не видят, и они на это ругаются.

## Архитектурные решения

**yt-dlp, ffmpeg и deno — внешние бинарники, не библиотеки.** deno нужен yt-dlp как JavaScript-рантайм для извлечения YouTube (без него часть форматов пропадает) и передаётся ему через `--js-runtimes`; самообновление yt-dlp (E6) рантайм не приносит, поэтому он поставляется так же, как остальные sidecar (решение владельца 2026-09-14, #114). Свою реализацию парсинга YouTube не пишем: формат отдачи меняется постоянно, yt-dlp обновляется быстрее любого нашего кода. Бинарники поставляются как Tauri sidecar в `src-tauri/binaries/` с суффиксом целевой тройки (`yt-dlp-x86_64-apple-darwin` и т.п.).

**Вся тяжёлая работа — в Rust.** Фронтенд не запускает процессы и не трогает файловую систему напрямую. Взаимодействие: `invoke` для команд, события Tauri для прогресса.

**Прогресс — через события, не через polling.** yt-dlp пишет прогресс в stdout; парсим его в Rust и эмитим событие на каждое задание (`download://progress` с id задачи). Фронтенд слушает и обновляет Pinia-стор. Никаких таймеров, опрашивающих бэкенд.

**Очередь — источник истины в Rust.** Состояние задачи (`Queued | Fetching | Downloading | Merging | Done | Failed | Cancelled`) живёт в менеджере очереди и переживает перезапуск UI. Стор на фронтенде — проекция, а не хозяин данных.

**Отмена обязательна на каждом этапе.** Долгие операции (скачивание, merge) должны корректно убивать дочерний процесс и подчищать частичные файлы.

**Хранилище раздельное.** История загрузок — SQLite (`rusqlite`, bundled) с версионированными миграциями: она растёт, по ней нужны поиск и сортировка, а запись должна быть атомарной. Настройки — отдельный JSON с записью через временный файл и переименование. Схема и миграции заводятся до первой реализации, которая в них пишет.

**Ошибки типизированные, не строки.** Отдельно выделяются «требуется вход», «нет сети», «недоступно в регионе», «yt-dlp устарел»: пользователь должен понимать, что делать, а не читать stderr.

**Пути и имена файлов санитизируются в Rust.** Заголовки роликов содержат символы, недопустимые в путях Windows, и потенциально `../`. Ни один компонент пути не строится из непроверенного ввода.

## Долговечность и естественное поведение

Требование владельца: программа должна работать как можно дольше и вести себя как обычный пользователь. Отсюда инварианты, которые не пересматриваются по ходу задач:

- Официальный YouTube Data API не используется — yt-dlp обращается к тем же эндпоинтам, что и веб-плеер.
- Собственный парсер выдачи не пишется никогда. Любой свой код отстанет от изменений на стороне YouTube; yt-dlp реагирует на них за дни.
- Соединение прямое, с машины пользователя, без промежуточных серверов. Системные настройки прокси уважаются.
- Число соединений дефолтное. Агрессивное распараллеливание отличает загрузчик от человека и провоцирует ограничения.
- Главный инструмент долгой жизни — обновляемый yt-dlp отдельным контуром (см. ниже).

## Два независимых контура обновления

Их нельзя смешивать: у них разная частота, разный риск и разный механизм.

**1. yt-dlp — часто, без релиза приложения.** YouTube ломает извлечение регулярно, и вшитый в релиз бинарник устаревает за недели. Приложение обновляет yt-dlp самостоятельно, отдельно от собственной версии; иначе каждая поломка на стороне YouTube требует выпуска нового релиза.

**2. Само приложение — плагин `updater` Tauri 2, редко и с подписью.** Приложение периодически проверяет манифест в GitHub Releases, сравнивает версии, скачивает и устанавливает апдейт. Следствия, обязательные к соблюдению в релизном процессе:

- Подпись обязательна: minisign-пара (`tauri signer generate`), публичный ключ — в `tauri.conf.json`, приватный — в секретах CI (`TAURI_SIGNING_PRIVATE_KEY`). Неподписанный апдейт не установится — это защита от подмены артефакта.
- **Linux-релизы выпускаются как AppImage**: плагин обновляет только его, `.deb`/`.rpm` обновляются системным пакетным менеджером.
- Проверка обновлений — не при каждом старте в блокирующем режиме; пользователь должен иметь возможность её отключить.

**Открытый вопрос: откуда раздавать релизы.** Репозиторий приватный, а релизные ассеты приватного репозитория не скачиваются без токена — вшить токен в приложение нельзя, он утечёт из бинарника вместе с доступом к исходникам. Значит, к моменту первого публичного релиза нужно решение: отдельный публичный репозиторий только под релизы, собственный эндпоинт обновлений, либо открытие основного репозитория. Пока приложение не раздаётся наружу, вопрос не блокирует работу.

Автообновление реализуется отдельным эпиком **после MVP**; до тех пор релизный процесс уже обязан соблюдать требования выше (AppImage, подпись в CI) — иначе первый же выпущенный релиз не сможет обновиться.

## Конвенции

- Rust: ошибки — `thiserror` в домейне, конвертация в сериализуемый тип на границе `#[tauri::command]`. `unwrap()` в продакшен-путях недопустим.
- Vue: только Composition API и `<script setup>`. Один стор Pinia на домен, без общего «god store».
- Типы, пересекающие границу Rust↔TS, объявляются один раз в Rust (`src-tauri/src/types.rs`) и **генерируются** в `src/types/generated/` — расхождение ловится в CI, а не в рантайме (TL-51). Руками TS-зеркало не пишется.
- Каждый новый формат/качество/постпроцессинг покрывается тестом на уровне `downloader`/`ffmpeg` с фикстурой вывода yt-dlp, без сетевых вызовов в тестах.

## Ресурсы машины

Тестовых контейнеров в проекте нет, но полная сборка Tauri (`npm run tauri build`, холодный `cargo build`) грузит машину сопоставимо: в каждый момент её ведёт **один** агент во всём проекте. Исполнители областей проверяют свою работу быстрыми командами (`cargo test`, `cargo clippy`, `npm run type-check`), полную сборку инициирует ведущий разработки.

**Полный прогон — только `cargo test --locked -- --test-threads=2`** (2026-09-17). С дефолтной параллельностью на этой машине (8 ядер) под нагрузкой собственного прогона падают тесты с жёстким потолком времени: `a_recognized_version_token_passes_the_same_filter_as_its_line` и `truncates_a_long_stderr_tail_to_the_configured_character_limit` (потолок 5 с, приходит `Timeout` с `duration_ms: 5004`), `os_reveal…hanging_launcher_is_killed_at_the_ceiling` (процесс убит по потолку 3 с раньше, чем успел записать stderr). Набор падающих меняется от прогона к прогону, узкий фильтр всегда зелёный, чужого cargo при этом нет. Замер: дефолт — 1029 passed / 3 failed за 66 с, два потока — 1033 passed / 0 failed за 102–123 с. Долг — #74; лечится рандеву вместо срока (как #38), а не поднятием потолка. Пока не закрыт, красное от дефолтной параллельности **не отличить от настоящей поломки**.

**Ожидание свободного cargo — `while ps -axo comm | grep -qxE 'cargo|rustc'; do sleep 15; done`.** Вариант `pgrep -f 'cargo|rustc'` находит собственную оболочку (её командная строка содержит эти слова) и ждёт вечно. Все worktree делят один `CARGO_TARGET_DIR`, поэтому чужая сборка перезаписывает `target/debug/*` прямо под тестами, которые запускают оттуда процессы: так уже получено красное, не связанное с кодом.

## Границы продукта

Приложение — GUI-обёртка над yt-dlp. Обход платных подписок, DRM и региональных ограничений в задачи проекта не входит и не реализуется. Ответственность за соблюдение условий сервиса и авторских прав при скачивании конкретного ролика лежит на пользователе — это стоит отразить в UI при первом запуске.

**E3 — скачивание ролика.** Десять задач: контракт и зеркало, санитизация имени, разбор прогресса, склейка своим ffmpeg, классификация исхода и политика повторов, оркестрация, панель, диалог выхода, разрешение на закрытие окна. Итоги — в `epics/E3-skachivanie-rolika.md`.

**Что работает в E3 и стоит помнить.** Скачивание делало два обращения к YouTube на ролик. С TL-48 (#50, 2026-09-13) загрузка идёт одним запуском `-f V,A`, склейка — своим ffmpeg, потоки различаются по имени файла, выпавший формат определяется по строке `[info] … Downloading N format(s)` (её хрупкость — #104). Предел попыток при обрыве — восемь: замер показал, что после выключения сети на 45 с связь возвращается к 155-й секунде. Таймаут сокета укорочен вдвое — решение ведущего, цена записана в файле эпика.

**Что сработало в трёх эпиках подряд и стоит повторять.** Ревью проверяет утверждения, а не читает код: распаковывает бинарник, чтобы вытащить константы; прогоняет миллионы сгенерированных имён; запускает инструмент офлайн, чтобы увидеть, что он делает с аргументами. Правки доказываются мутациями — сначала ломают то, что тест обязан поймать. Расхождения документа с живыми данными ловятся измерением. Чёрные списки заменяются белыми: в E3 чёрный подвёл дважды подряд.

**Корневой вывод, подтверждённый трижды.** Дефекты этого проекта живут в слоях, которые не видит ни один тест: между bundle и dev-режимом, между webview и ядром, между съёмкой фикстуры и настоящим выводом процесса. Приёмочные критерии проверяются на `npm run tauri build` с монтированием `.dmg`; **визуальный проход владельца — часть приёмки**, потому что у автоматизации нет разрешений macOS на запись экрана и управление интерфейсом. Приём с временным хуком в релизной сборке допустим, но должен быть назван в отчёте отдельно от настоящего пути.

**Режим работы без CI — решение владельца.** Мержим по локальным прогонам, все задачи без исключения, включая трогающие зависимости и сборку. Цена названа и принята: **Linux и Windows не собирает никто**. Матрица `build` — единственный сторож расхождений фич по таргетам (так прятался дефект `flate2`, невидимый на macOS), и на время блокировки этого сторожа нет. Долг копится в #70; прогнать матрицу, как только CI вернётся.

Пока CI мёртв, ведущий обязан прогонять локально сам, а не доверять отчёту исполнителя: `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo fmt --check`, `npm run type-check`, `npm run lint`, `npm test`.

**Что знать про сам CI, когда он вернётся.** Проверки не обязательны технически (branch protection недоступна без Pro, решение владельца — дисциплина), поэтому ведущий не мержит, не посмотрев `gh pr checks`. Джоб `test` идёт только на macOS: на Linux `cargo test` не завершается (#37). Джоб `build (macos-13)` не стартует (#39) — смотреть надо статусы джобов, а не прогона.

**Про архитектуру (вопрос владельца, закрыт).** Встраивать yt-dlp и ffmpeg библиотеками не будем: линковка ffmpeg распространит GPL на наш код, встраивание yt-dlp сломает обновление отдельным контуром (E6) и лишит изоляции падений.

**Окружение.** `cargo` не в PATH: `export PATH="/opt/homebrew/opt/rustup/bin:$PATH"`. Перед полной сборкой смотреть `df -h`. Общий `target` (один на все worktree через `CARGO_TARGET_DIR`) растёт с каждым раундом проверок; когда свободного места меньше ~5 ГиБ и cargo никто не гоняет (`pgrep -f 'cargo|rustc'` пуст), место освобождает `cd src-tauri && cargo clean -p tube-leak` — удаляет артефакты только нашего крейта вместе с его инкрементальным кэшем, зависимости остаются (2026-09-14: 3,2 → 21 ГиБ). Удаление каталогов `target` через `rm -rf` в этой среде отклоняется разрешениями. В свежем worktree тесты требуют заглушек: `node scripts/ci/stub-binaries.mjs`, затем `TUBE_LEAK_ALLOW_STUB_YTDLP=1 cargo test`. После мержа ветки, меняющей `package-lock.json`, в основной копии сначала `npm ci`, потом локальный прогон: иначе `main` краснеет на неразрешённом импорте, и это выглядит как дефект кода (так было с TL-94, `@tauri-apps/plugin-dialog`).

**Типы границы генерируются, не пишутся руками (TL-51).** Объявляются в `src-tauri/src/types.rs` **выше** маркера `mod bindings;` — ниже их не видит ни один сторож. Зеркало лежит в `src/types/generated/` и коммитится; перегенерация — `TUBE_LEAK_UPDATE_TS_BINDINGS=1 cargo test`, обычный `cargo test` сверяет и падает при расхождении. Руками сгенерированное не править. На стороне TS списки вариантов объявляются литералом с `satisfies Record<Kind, true>`, а исчерпывающие `switch` закрываются `assertNever` — голого `switch` без `default` недостаточно, когда возвращаемый тип и так допускает `undefined`.

**Урок E5: ревью ловит слои, которых не видит зелёный прогон.** ACL-сторож сканировал только `@tauri-apps/api` и пропускал импорт плагина — диалог выбора папки упал бы на `.dmg` при зелёных тестах; живая зона на перемонтируемом узле молчала бы для VoiceOver; два решения ведущего («применяется последний ответ» и «пометки копятся») в коде столкнулись и теряли однократную пометку. Правило подтвердилось ещё раз: сторож проверяется мутацией против собственных границ, а мерж ветки, меняющей `package-lock.json`, требует `npm ci` в основной копии до прогона.

**Урок сессии, подтверждённый шесть раз подряд.** Дефект чаще оказывался не в коде, а в проверке: белый список, разошедшийся с Rust; шаг CI, замолкающий от красного линтера; сторож, ослеплённый собственным импортом; мутация, не доходящая до проверяемого кода; разбор имён каналов, тихо пропускавший непонятное; свежая правка сторожа, не подключённая вовсе. В большинстве случаев рядом стоял doc, утверждавший обратное. Отсюда правило: **утверждение сторожа о собственных границах проверяется наравне с тем, что он охраняет**, а правка сторожа доказывается не зелёными тестами, а их покраснением на живой мутации.

**Урок E6: установка перестала быть разрушительной, а проверка — доверчивой.**
`prepare::install` распаковывает в staging целиком и сносит прежнее дерево только
перед `rename` — гарантия «отказ не трогает рабочую установку» стала свойством
конструкции, а не договорённостью о том, с каким идентификатором сюда можно
звать. Цена: пик диска +124 МиБ, и правка затрагивает первый запуск (E1).
Идентификатор установки — тип с приватным полем и единственным конструктором за
белым списком: до TL-56 версия из метаданных апстрима уходила в `Path::join`
как есть, и запись файла вне каталога данных была воспроизведена запуском.

**Мутация проверяется до того, как ей верят.** За E6 шесть раз «красное» или
«зелёное» ничего не значило: несовпавший `sed`; `rsync`, вернувший старое время
файла (cargo прогнал прежний бинарник); `git checkout -- src`, не тронувший файл
вне индекса; комментарий, проглотивший открывающую скобку (код возврата 101 без
строки `test result` — это ошибка компиляции, а не падение теста); тест, который
проходил мимо проверяемого из-за соседнего механизма. Отсюда порядок: `grep`
после правки, `touch` перед прогоном, `test result` в выводе, восстановление из
снимка файла.

**Урок E4: «измерено» относится к измеренному, а не ко всему классу.** Белый
список форм ссылки расширяли по замеру настоящего yt-dlp — и обоснование
ведущего «ложное слипание невозможно, раз тождество измерено» оказалось верным
только для формы `watch?v=`. У форм с идентификатором в пути YouTube ставит
плейсхолдер (`videoseries`, `live_stream` — оба ровно 11 знаков, проверку формы
проходят), а настоящий адрес кладёт в query: две ссылки на разные плейлисты
давали один «ролик». Дефект был старше расширения — форма `/shorts/` названа
самим требованием. Поймал его не разбор кода, а попытка сделать код шире.

**Приём для замера чужого инструмента без сети.** yt-dlp печатает извлечённый
идентификатор в тексте ошибки **до** первого сетевого обмена, поэтому его
поведение снимается через заведомо мёртвый прокси (`--proxy http://127.0.0.1:1`):
матрица «шесть хостов × пять форм пути» проверена без единого обращения к сети.
Правило «в тестах сети нет» соблюдено, а ответ настоящий, а не предположение.

**Зависимость отклоняется измерением, а не оценкой.** Плагин единственности
приложения давал +4 крейта на macOS, +5 на Windows (третья версия windows-sys)
и **+35 на Linux** со второй асинхронной машинерией рядом с tokio; набор по
тройкам не совпадал — класс дефекта `flate2`. Заменён эксклюзивной блокировкой
файла: `fs4` уже в графе, фича `sync` пустая, `Cargo.lock` не изменился ни на
строку. Цена названа: второй запуск не поднимает окно первого (#84).
