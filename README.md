# tube-leak

Кросс-платформенное десктопное приложение для скачивания видео с YouTube.
GUI-обёртка над `yt-dlp` и `ffmpeg` (Tauri 2 + Vue 3). Подробнее об
архитектуре и соглашениях разработки — в `CLAUDE.md`.

## Минимальные версии ОС

| ОС | Минимальная версия |
|---|---|
| Windows | 10, сборка 1809 (October 2018 Update) и новее |
| macOS | 13 (Ventura) и новее |
| Linux | Ubuntu 24.04 LTS и новее (или эквивалентная по составу библиотек дистрибуция) |

Приёмка E1 идёт только на macOS (Р-6 эпика E1); Windows и Linux матрица
проверяется по мере готовности CI/машин (см. `CLAUDE.md`, «Что ждёт
владельца»).

## Установка

Скачайте инсталлятор под вашу ОС из GitHub Releases репозитория.
Приложение пока не подписано (см. «Два независимых контура обновления»
в `CLAUDE.md`) — первый запуск на macOS требует ручного обхода
Gatekeeper, см. ниже.

### macOS: первый запуск неподписанной сборки (Gatekeeper)

Сборка `tube-leak.app` не имеет подписи Apple Developer ID и не
нотаризована, поэтому Gatekeeper при первом двойном клике покажет
предупреждение «нельзя открыть, т.к. не удаётся проверить разработчика»
или предложит переместить приложение в корзину. Это ожидаемо и не
означает, что файл повреждён. Обойти один раз:

1. **Через Finder (рекомендуется).** Найдите `tube-leak.app` в Finder,
   кликните на нём правой кнопкой мыши (или зажмите `Control` и
   кликните) → «Открыть» (Open). В диалоге снова нажмите «Открыть» —
   после этого разового подтверждения приложение будет запускаться
   обычным двойным кликом.
2. **Через терминал.** Если пункта «Открыть» в контекстном меню нет
   (актуально для новых версий macOS) либо приложение всё равно
   блокируется, снимите карантинный атрибут вручную:

   ```bash
   xattr -d com.apple.quarantine /path/to/tube-leak.app
   ```

   Замените `/path/to/tube-leak.app` на реальный путь, например
   `/Applications/tube-leak.app`.

Оба способа делают одно и то же — снимают расширенный атрибут
`com.apple.quarantine`, которым macOS помечает всё, что скачано из
интернета браузером.

<a id="sidecar-blocked-by-av-gatekeeper"></a>
### Служебный экран показывает «не отвечает»: антивирус или Gatekeeper блокирует sidecar

При первом запуске tube-leak проверяет, что `yt-dlp`, `ffmpeg` и `deno`
действительно запускаются (см. `src/components/SidecarStatusRow.vue`).
Если строка проверки зависает и в итоге показывает статус
**«не отвечает» (таймаут)**, это почти всегда не проблема сборки, а
проверка бинарника сторонним ПО в фоне.

`deno` — JavaScript-рантайм. Сам по себе приложению он не нужен: его
запускает yt-dlp, чтобы пройти JavaScript-проверки YouTube, и без него
часть форматов пропадает. Для антивируса и Gatekeeper это такой же
исполняемый файл, как два других, и задержать его запуск они могут
так же.

Лежат они в разных местах: `ffmpeg` и `deno` — внутри бандла рядом с
приложением, `yt-dlp` — в каталоге данных приложения, куда он
распаковывается при первом запуске отдельным этапом подготовки (см. ниже
«Этап подготовки при первом запуске»).

- **Windows.** Windows Defender (или сторонний антивирус) может
  сканировать `yt-dlp.exe`/`ffmpeg.exe`/`deno.exe` при первом запуске в песочнице
  либо ставить исполнение на паузу до завершения проверки —
  быстро выполняемая команда зависает на десятки секунд, и наша
  проверка укладывается в таймаут раньше, чем антивирус отпускает
  процесс.
  **Решение:** добавьте в исключения антивируса оба места, где лежат
  эти файлы: папку с установленным `tube-leak.exe` (обычно
  `C:\Program Files\tube-leak\` или папка, куда распакован портативный
  билд) — там `ffmpeg.exe` и `deno.exe`, — и каталог данных приложения
  `%APPDATA%\dev.execaus.tubeleak\yt-dlp\`, куда распаковывается
  yt-dlp. Либо явно разрешите `yt-dlp.exe`, `ffmpeg.exe` и `deno.exe` как
  доверенные приложения — все три: `deno.exe` запускается не только
  проверкой служебного экрана, но и самим yt-dlp при разборе ссылки.
  ЖИВЬЁМ НЕ ПРОВЕРЕНО: машины на Windows в проекте нет (Р-6), пути
  выведены из раскладки Tauri, а не из наблюдения.
- **macOS.** Даже после того как вы обошли Gatekeeper для самого
  `tube-leak.app` (см. выше), карантинный атрибут может остаться на
  вложенных `ffmpeg` и `deno` — Gatekeeper проверяет **каждый** исполняемый файл
  при первом запуске отдельно, а не только сам `.app`-бандл. По
  устройству macOS-бандла Tauri 2 (подтверждено по исходникам
  `tauri-bundler`, `crates/tauri-bundler/src/bundle/macos/app.rs` и
  `settings.rs` в репозитории `tauri-apps/tauri`) внешние бинарники
  (`externalBin`) копируются **не в `Contents/Resources/`, а в тот же
  каталог, где лежит основной исполняемый файл приложения** —
  `Contents/MacOS/`, с именем без суффикса целевой тройки:

  ```
  /Applications/tube-leak.app/Contents/MacOS/ffmpeg
  /Applications/tube-leak.app/Contents/MacOS/deno
  ```

  **Решение:** снимите карантин рекурсивно со всего бандла (это
  затронет и вложенные бинарники):

  ```bash
  xattr -dr com.apple.quarantine /Applications/tube-leak.app
  ```

  Если это не помогло, снимите атрибут точечно:

  ```bash
  xattr -d com.apple.quarantine /Applications/tube-leak.app/Contents/MacOS/ffmpeg
  xattr -d com.apple.quarantine /Applications/tube-leak.app/Contents/MacOS/deno
  ```

  `yt-dlp` в бандле не лежит: приложение распаковывает его в
  `~/Library/Application Support/dev.execaus.tubeleak/yt-dlp/`. Если
  что-то в этом каталоге испортилось, его можно просто удалить целиком —
  при следующем запуске приложение повторит этап подготовки.

Если после исключения в антивирусе/снятия карантина статус всё ещё
«не отвечает» — откройте блок «Подробнее» в этой же строке служебного
экрана: там будет путь до бинарника, код ошибки ОС и хвост `stderr`,
которые стоит приложить при обращении за помощью (issue в репозитории
проекта).

<a id="first-run-preparation"></a>
### Этап подготовки при первом запуске

Первый запуск после установки занимает около полуминуты и показывает ход
подготовки. Это не зависание: приложение распаковывает yt-dlp в каталог
данных и один раз прогоняет его, чтобы macOS проверила подписи всех
файлов дерева. Дальнейшие запуски укладываются в доли секунды.

Цена этой проверки — примерно 0,4 с за каждый только что созданный
исполняемый файл, а в дереве yt-dlp их около сотни; результат ОС
запоминает и переиспользует. Если бы приложение вместо этого запускало
однофайловую сборку yt-dlp, та распаковывала бы себя во временный каталог
на каждом запуске, и полминуты платил бы каждый запуск и каждое
скачивание.

Этап повторяется, если приложение обновилось и принесло другую версию
yt-dlp, если каталог данных удалили — и если ОС забыла результат
проверки. Приложение определяет это само, пробуя запустить yt-dlp; когда
дерево уже готово, этап не показывается вовсе.
